# Лабораторная работа №3

## Тема

**Разработка модульных тестов для Django-приложения**

## Постановка задачи

В рамках лабораторной работы №3 необходимо разработать набор автоматизированных тестов для Django-приложения, созданного в рамках предыдущей лабораторной работы.

Основная цель работы — проверить корректность работы моделей, бизнес-логики и представлений приложения с помощью модульных тестов.

В проекте особое внимание уделено тестированию:

- создания и хранения объектов моделей;
- связей между моделями;
- методов расчета накопительной скидки;
- расчета общей суммы покупок;
- расчета суммы скидки;
- расчета итоговой суммы;
- корректности работы представлений;
- формирования HTTP-ответов;
- создания объектов через POST-запросы;
- обработки граничных значений скидки;
- поведения приложения при повторных покупках.

## Краткое описание проекта

В качестве основы используется Django-приложение магазина, разработанное в рамках лабораторной работы №2.

Приложение работает с тремя основными сущностями:

- **Product** — товар с названием и ценой;
- **Customer** — покупатель с именем и адресом;
- **Purchase** — покупка, связывающая покупателя с товаром и содержащая дату создания.

Главная страница отображает товары и покупателей.

Для покупателя рассчитываются:

- общая сумма совершенных покупок;
- размер накопительной скидки;
- сумма скидки;
- итоговая сумма после применения скидки.

В текущей реализации скидка зависит от общей накопленной стоимости покупок:

| Общая сумма покупок | Скидка |
| -------------------- | ------ |
| менее 5 000 руб.    | 0%     |
| от 5 000 руб.       | 3%     |
| от 10 000 руб.      | 5%     |
| от 20 000 руб.      | 10%    |

Лабораторная работа №3 сосредоточена прежде всего на проверке этой логики и поведения приложения с помощью автоматизированных тестов.

## Организация модульных тестов

### `test_models.py`

В файле `test_models.py` реализованы тестовые классы:

- `ProductTestCase`;
- `CustomerTestCase`;
- `PurchaseTestCase`.

Каждый тестовый класс наследуется от `django.test.TestCase`.

Для подготовки исходных данных используется метод `setUp()`, в котором создаются необходимые объекты базы данных.

### `test_views.py`

В файле `test_views.py` реализованы тестовые классы:

- `IndexViewTestCase`;
- `PurchaseCreateViewTestCase`;
- `CustomerCreateViewTestCase`.

Для проверки HTTP-взаимодействия используется стандартный Django Test Client через `self.client`.

Для проверки маршрутов также используется `django.urls.reverse`, хотя основная часть HTTP-тестов обращается к соответствующим URL приложения.

## Реализуемая бизнес-логика и ее тестирование

Основные вычисления находятся в модели `Customer`.

Метод `total_spent()` вычисляет общую стоимость всех покупок:

```python
def total_spent(self):
    return sum(
        purchase.product.price
        for purchase in self.purchases.select_related('product').all()
    )
```

Размер скидки определяется методом `discount_percent()`:

```python
def discount_percent(self):
    total = self.total_spent()

    if total >= 20000:
        return 10
    if total >= 10000:
        return 5
    if total >= 5000:
        return 3

    return 0
```

Сумма скидки:

```python
def discount_amount(self):
    return self.total_spent() * self.discount_percent() / 100
```

Итоговая сумма:

```python
def total_with_discount(self):
    return self.total_spent() - self.discount_amount()
```

Все перечисленные методы покрыты автоматизированными тестами.

Таким образом, тестируется как каждая отдельная функция бизнес-логики, так и их совместная работа.

## Принцип работы тестовой базы данных

При запуске тестов Django автоматически создает отдельную тестовую базу данных.

Тесты выполняются изолированно от основной базы данных, а после завершения тестирования тестовая база удаляется.

Это позволяет:

- создавать тестовые объекты непосредственно во время выполнения тестов;
- проверять создание, изменение и удаление данных;
- не изменять рабочие данные приложения.

Подготовка тестовых данных выполняется в `setUp()` каждого тестового класса.
